# reinvent-scribe 設計書

2026-11-25 / 対象: re:Invent 2026 (11/30–12/4, ラスベガス)

## 意図と背景

re:Invent の英語セッションを現地で録音・リアルタイム文字起こしし、日本語議事録と
マネージャー向けの1日行動サマリーを作るためのローカルアプリ。PoC を兼ねる。
会場 Wi-Fi は信用できない前提のため、文字起こしはローカル (faster-whisper) が主。
出発まで約5日。作り込みより「確実に録れて確実に残る」が最優先。

## ゴール

1. 英語のリアルタイム文字起こし(ローカル、オフライン動作)
2. 音声の録音・保存
3. 準リアルタイムの日本語要約: オンライン時、数分ごとに直近の文字起こしを LLM API に投げ「ここまでの日本語要約」を画面に積んでいく。オフラインなら字幕のみに自動劣化
4. セッション単位の Markdown 出力(ブログ記事調の日本語記事を生成するための元データ。夜に Claude へ渡す用)
5. 1日の出張日報生成: 上司へ Slack で共有する日報。セッションのメタ情報+手入力メモ+LLM API による各セッション要点。ユーザーがコピーして Slack に手動投稿
6. 文字起こしチャット: 文字起こしを文脈に、もっと知りたい点を UI のチャットフォームから LLM に質問できる(オンライン時のみ)
7. 話者識別: 将来対応。セッション終了後に保存済み WAV へオフラインの話者分離をかけてラベルを付け直す方式を想定。今回のスコープ外だが、WAV を残す設計がその前提
8. Mac (M3 Pro, 18GB) で動作。将来 Windows の同僚にも GitHub clone + README で配布可能

## 非ゴール / アンチゴール

- Slack への自動投稿はしない(コピー用テキストを出すまで)
- 日本語のリアルタイム逐語訳・字幕はしない(準リアルタイム「要約」のみ。精緻な日本語記事化は夜の Claude 運用)
- 話者識別は今回は実装しない(将来対応。上記ゴール6)
- デスクトップアプリ化(.dmg/.exe)はしない。将来の選択肢として残す
- 現地の人との会話翻訳は対象外
- アンチゴール: 録音・保存が不安定で当日データを失うこと。機能を足して安定性を犠牲にしない

## 制約

- 納期: 実質5日(11/30 のセッション開始までに使える状態)
- オフラインで必須機能(録音+文字起こし+Markdown 出力)が完結すること
- LLM 要約(準リアルタイム・日次)はオンライン時のみ動けばよい。オフラインでも録音・字幕・Markdown 出力は完結すること
- 配布: GitHub リポジトリ。clone → README のセットアップ手順で Mac/Windows 両対応

## 検討した案

- **案A: Python + ブラウザ UI(採用)** — FastAPI + faster-whisper。クロスプラットフォーム、5日で確実、UI も作れる。配布は Python 環境が前提だが対象が同僚エンジニアなので許容。
- 案B: Tauri/Electron + whisper.cpp — 配布は綺麗だがネイティブ同梱とクロスビルドで納期リスク大。不採用。
- 案C: CLI のみ — 最小工数だがセッション中の視認性と配布性で劣る。不採用。

ユーザーは案Aを選択。

## アーキテクチャ(ビルダーへの指針)

- **バックエンド**: Python 3.11+, FastAPI + uvicorn。WebSocket でブラウザに字幕をストリーム。
- **文字起こし**: faster-whisper。モデルは既定 `small.en`(int8)。M3 Pro/CPU int8 でリアルタイム比 1x 以上を初回起動時にベンチし、遅ければ `base.en` に自動フォールバック。モデルは初回にダウンロードしキャッシュ(出発前に必ず一度起動する旨を README に明記)。
- **音声入力**: sounddevice (PortAudio) でマイクキャプチャ。16kHz mono を文字起こしへ、同時に元音声を WAV で逐次書き込み(クラッシュしても途中まで残る)。
- **VAD/チャンク**: faster-whisper 内蔵 VAD を利用し、数秒単位のセグメントで逐次確定字幕を出す(部分仮説の表示は不要。確定セグメントの追記のみで十分)。
- **UI**: 単一ページ。見た目は「オシャレでスタイリッシュ」をユーザーが明示要望 — 最近流行のアニメーション系 UI パーツ(グラスモーフィズム/グラデーション、録音中の波形・パルス表示、字幕や要約のフェード/スライドイン、マイクロインタラクション)を取り入れる。ただしビルドツール不要の構成を維持(CDN 不可なら同梱)し、アニメーションが文字起こしの安定性を損なわないこと。セッション開始フォーム(セッションID・タイトル・メモ)、録音開始/停止、字幕の流れる表示、本日のセッション一覧、サマリー生成ボタン。
- **データ配置**: `./data/YYYY-MM-DD/<日付>_<開始時刻>_<セッションID>/` に `audio.wav`、`transcript.md`、`meta.json`(ID、タイトル、開始/終了時刻、メモ)。
- **transcript.md**: ヘッダ(セッションID・タイトル・日時・メモ)+タイムスタンプ付き英語文字起こし。固定テンプレートは付けない。最終的な日本語記事は「セッションの内容や重要な点が理解できるブログ記事調」を目指す — 準リアルタイム要約・日次サマリーのプロンプト、および夜の Claude 工程への指示文(リポジトリに同梱する prompt 例)をこのテイストで書く。
- **2パス文字起こし**: セッション中は `small.en` でリアルタイム字幕、セッション停止後に保存 WAV へ高精度モデル(`large-v3-turbo` 系)で再文字起こしを自動実行し `transcript_hq.md` を生成。夜の Claude 工程には高精度版を渡す。
- **開始摩擦の最小化(体験改善)**: 起動時にブラウザを自動で開く。セッション予定 CSV(`sessions.csv`: 日付,開始時刻,ID,タイトル)を置いておけば、現在時刻から該当セッションを推定してID・タイトルを自動入力し、1クリックで録音開始できる。
- **用語対応**: `glossary.txt`(AWS 用語リスト)を Whisper の `initial_prompt` に注入。リポジトリに汎用 AWS 用語の初期リストを同梱し、ユーザーが編集できることを README に明記。`initial_prompt` は約224トークンで切り詰められるため、超過時は先頭から使い警告を出す。誤認識の事後修正は夜の Claude 工程に委ねる(アプリ内では置換辞書を実装しない — 納期優先の私の判断)。
- **LLM プロバイダ抽象化**: 要約(準リアルタイム・日次とも)は特定ベンダーに固定しない。OpenAI 互換 Chat Completions API を既定インターフェースとし、`LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` の環境変数で切り替え可能(例: OpenAI gpt-4o-mini、Google Gemini Flash、Anthropic は互換エンドポイント経由)。既定は安価なモデルを README で推奨。コスト目安: 1セッション1時間の要約で数円以下のモデルを選ぶ。
- **準リアルタイム日本語要約**: 録音中、約3〜5分ごと(設定可)に直近の確定文字起こしを LLM に送り、累積の日本語要約を UI のサイドペインに追記。失敗・オフライン時は静かにスキップし次回リトライ。文字起こし・録音の動作には一切影響させない。
- **文字起こしチャット**: UI にチャットフォームを設け、現在(または選択した)セッションの文字起こしを文脈として LLM に質問できる(「さっきの新機能の詳細は?」など)。同じ LLM プロバイダ設定を使用、オンライン時のみ。会話履歴はセッションディレクトリに `chat.md` として保存。長い文字起こしは直近+先頭を優先して文脈に詰める(詳細はビルダーに委ねる)。録音・文字起こしの動作には影響させない。
- **日次サマリー(出張日報)**: 上司へ Slack で送る出張日報。ボタンで当日の全 meta.json + transcript を集約し、LLM で日報形式の日本語 Markdown を生成 — 冒頭に本日の行動概要(出席セッション一覧: 時刻・ID・タイトル)、続いて各セッションの要点(2〜4行、業務報告として読める粒度)、所感・特筆事項(手入力メモから)。画面表示+`data/YYYY-MM-DD/daily_summary.md` 保存、ユーザーがコピーして Slack に手動投稿。オフライン/キー無しならメタ情報+メモのみの日報に劣化動作。
- **Windows 対応**: 依存は全てクロスプラットフォームの PyPI パッケージに限定。OS 依存コードを書かない。README に Mac/Windows 両方の手順。

## ビルダーに委ねる点

- WebSocket のメッセージ形式、UI の見た目の詳細
- WAV の逐次書き込み実装の詳細(クラッシュ耐性が保てれば手段は問わない)
- faster-whisper のパラメータ調整(beam size 等)

## 私(設計者)の判断として記録する点

- モデル既定 `small.en` + 自動フォールバック(精度と実時間性のバランス)
- 用語の事後置換辞書は作らない(Claude 工程で直す)
- 部分仮説のリアルタイム表示はしない(確定セグメント追記のみ)
- 録音フォーマットは WAV(堅牢性優先。容量は1セッション約200MB/1h、1週間で数GB — 許容と判断)
- セッションメモは録音中・終了後も編集可能(meta.json は mutable)。開始フォームだけでは実運用に合わないため
- glossary.txt は汎用 AWS 用語の初期リストを同梱(ユーザー編集前提)
